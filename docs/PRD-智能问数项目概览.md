# 智能问数项目概览 PRD

## 1. 项目定位

本项目建设一个面向经营分析场景的智能问数系统。用户通过自然语言提出数据问题，系统基于元数据、指标口径、字段关系和真实数据源生成 SQL，经过安全校验后执行查询，并返回结构化结果和可视化结果。

系统不是普通聊天助手，核心产出是可执行、可审计、可复盘的查询过程，包括用户问题、召回上下文、生成 SQL、校验结果、执行结果和错误信息。

## 2. 第一阶段业务范围

第一阶段优先跑通抖音主题域的数据和元数据，不以教程中的电商教学表为实际落地表。

第一阶段目标：

- 接入抖音主题域数据表。
- 建立抖音主题域的表级元数据和字段级元数据。
- 支持基于抖音主题域的自然语言问数。
- 跑通元数据同步、SQL 生成、SQL 校验、SQL 执行、结果返回的完整链路。
- 保留后续扩展到更多主题域、更多数据源、更多指标口径的架构空间。

教程中的 `fact_order`、`dim_product`、`dim_customer`、`dim_region`、`dim_date` 只作为理解维度建模和 NL2SQL 链路的参考，不作为实际业务模型约束。

## 3. 元数据建设方式

未来元数据的主要维护入口不是本地配置文件，而是钉钉 AI 表格。

预期流程：

1. 人工或脚本将原始元数据导入钉钉 AI 表格。
2. 借助钉钉 AI 字段能力自动生成字段描述、业务含义等说明。
3. 业务人员或项目负责人补充指标计算口径、字段间依赖、字段血缘和使用注意事项。
4. 系统通过钉钉开放平台接口定时读取钉钉 AI 表格数据。
5. 同步任务将钉钉中的元数据写入项目自己的元数据数据库。
6. 元数据数据库再驱动字段召回、指标理解、SQL 生成和 SQL 审核。

该设计下，钉钉 AI 表格是元数据协作和人工治理入口，项目数据库是运行时权威元数据存储。

## 4. 元数据模型

当前设计不强制区分“指标”和“字段”。指标可作为带计算公式、业务口径和依赖关系的特殊字段元数据来管理。

### 4.1 表元数据

表元数据至少包含：

- 主题域
- 数仓层级
- 库名
- 表名
- 表中文名
- 表说明
- 业务对象
- 表粒度
- 主键
- 更新频率
- 分区字段
- 数据来源系统
- 负责人
- 适用场景
- 不适用场景
- 使用注意事项

### 4.2 字段元数据

字段元数据至少包含：

- 归属表名
- 字段名
- 字段中文名
- 字段描述
- 数据类型
- 字段类型
- 计算公式
- 直接依赖
- 业务含义
- 使用注意事项

字段类型包括：

- 标识字段
- 属性字段
- 度量字段
- 时间字段
- 技术字段

## 5. 关键产品原则

- 元数据质量优先于模型技巧。SQL 生成准确率首先依赖清晰的表说明、字段说明、业务口径和依赖关系。
- SQL 必须可审计。每一次问数都要保留问题、上下文、SQL、校验结果、执行结果和耗时。
- 不盲目照搬教程。教程提供工程思路，实际实现以当前业务数据、运维资源和长期可维护性为准。
- 不为了省资源牺牲长期架构。第一阶段可以聚焦抖音主题域，但底层设计应支持后续扩展，而不是做难以迁移的临时方案。
- 真实密钥、数据库超级管理员账号和服务器管理员账号不得写入 Git 仓库。
