# SQL Review Rules

取数 Agent 默认只允许执行只读查询。所有由模型生成的 SQL 必须先经过审查，再进入执行阶段。

## Hard Blocks

- 禁止执行非只读语句：`INSERT`、`UPDATE`、`DELETE`、`DROP`、`TRUNCATE`、`ALTER`、`CREATE`、`REPLACE`、`GRANT`、`REVOKE`、`CALL`、`EXECUTE`、`LOAD`。
- 禁止多语句执行；单次请求只能包含一条 SQL。
- 禁止访问非授权数据库。
- 禁止 `SELECT *`，除非处于人工批准的调试模式。
- 禁止包含明显敏感字段的查询结果直接返回，例如密码、token、secret、身份证号、手机号全量字段。

## Risk Review

以下情况默认提示风险，进入人工确认或自动改写：

- 多表查询缺少明确 `JOIN ... ON` 条件。
- `JOIN` 条件中没有使用等值关联。
- 表别名之间没有可识别的关联路径，存在笛卡尔积风险。
- 聚合查询没有合理的时间范围过滤。
- 查询预估扫描大表且没有时间、主键、状态等过滤条件。
- `LIKE '%keyword%'` 作用在大表高基数字段上。
- `ORDER BY` 未配合合理 `LIMIT`。
- 无 `LIMIT` 的查询不会被自动改写，也不会因这一点被硬拦截；审查器只记录提示，是否收敛范围由业务分析场景决定。
- 子查询、窗口函数、CTE 层级过深，可能导致慢查询。

## Execution Defaults

- 默认查询超时：`30s`。
- 默认只连应用只读账号。
- 运维账号只允许由人工明确触发的管理脚本使用。
- 每次执行记录：用户问题、生成 SQL、审查结果、执行耗时、返回行数、错误信息。

## Human Approval

以下场景必须人工确认：

- 需要临时放宽行数限制。
- 需要查询敏感字段。
- 需要跨库查询。
- 需要执行数据库运维语句。
- SQL 审查器判断存在笛卡尔积或大表全扫描风险。
