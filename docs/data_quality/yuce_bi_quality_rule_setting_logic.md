# 预策 BI 数据质量检查规则配置逻辑

说明书入口：https://alidocs.dingtalk.com/i/nodes/ydxXB52LJq79MD9NCQ3XY0A6WqjMp697

来源章节：`9.1.3.11 数据质量检查规则`

本文用于把当前数据质量治理候选规则，尽量转换成预策 BI 的内置质量检查规则配置项。原则是：能用表规则/字段规则配置的，不优先写 SQL 规则；SQL 规则只作为复杂业务口径、跨表对账、字段组合唯一性、特殊类型转换的兜底。

## 1. 规则体系

预策 BI 的质量检查规则主要分为两类：

| 规则类别 | 配置对象 | 适合解决的问题 |
| --- | --- | --- |
| 表规则 | 整张表或单日数据 | 行数、表大小、日分区/业务日期是否有数据、行数波动 |
| 字段规则 | 单个字段 | 最大值、最小值、唯一值个数、空值、重复值、枚举异常 |

其中“单日”类规则需要日期参数；“全表”类规则通常不需要日期参数。

## 2. 表规则

| BI 模板名称 | 阈值类型 | 是否需要日期参数 | 推荐使用场景 |
| --- | --- | --- | --- |
| 全表行数，固定值 | 固定值 | 不需要 | 小表、维表、非日更静态表的非空检查 |
| 单日行数，固定值 | 固定值 | 需要 | 日更 T+1 表，检查昨天业务日期是否有数据 |
| 全表行数，1、7、30 天波动率 | 百分比 | 不需要 | 全表追加型表的总体规模波动观察 |
| 单日行数，1、7、30 天波动率 | 百分比 | 需要 | 日更表按昨天业务日期做行数波动检查 |
| 全表行数，1 天差值 | 固定值 | 不需要 | 非分区表或累计表的日增量异常 |
| 全表行数，上周期差值 | 固定值 | 不需要 | 周期性累计表或固定周期汇总表 |
| 表大小，固定值 | 固定值 | 不需要 | 防空表、异常清表、存储突变 |
| 表大小，1 天波动率 | 百分比 | 不需要 | 全表存储量日波动 |
| 表大小，7 天波动率 | 百分比 | 不需要 | 全表存储量周波动 |
| 表大小，上周期差值 | 固定值 | 不需要 | 周期性存储变化 |
| 表大小，相比 1 天前的差值（字节） | 固定值 | 不需要 | 存储字节级差异检查 |

## 3. 字段规则

| BI 模板名称 | 适用字段类型 | 阈值类型 | 推荐使用场景 |
| --- | --- | --- | --- |
| 最小值，1、7、30 天波动率 | 数值 | 百分比 | 数值指标的下界波动，如金额、数量、库存 |
| 单日最小值，1、7、30 天波动率 | 数值 | 百分比 | 日更指标按昨天业务日期检查 |
| 最大值，1、7、30 天波动率 | 数值 | 百分比 | 数值指标极值异常 |
| 单日最大值，1、7、30 天波动率 | 数值 | 百分比 | 日更指标昨天极值异常 |
| 唯一值个数，固定值 | 字符串/数值 | 固定值 | 维度覆盖数、店铺数、商品数、账号数 |
| 唯一值个数，1、7、30 天波动率 | 字符串/数值 | 百分比 | 核心对象数波动 |
| 空值个数，固定值 | 字符串/时间/数值 | 固定值 | 主键、业务日期、核心字段非空 |
| 空值个数/总行数，固定值 | 字符串/数值 | 固定值 | 空值率控制，适合允许少量空值的字段 |
| 重复值个数/总行数，固定值 | 字符串/数值 | 固定值 | 单字段重复率控制 |
| 重复值个数，固定值 | 字符串/数值 | 固定值 | 单字段唯一性检查 |
| 唯一值个数/总行数 | 字符串/数值 | 固定值 | 识别字段区分度异常 |
| 枚举值，全表，异常值数量（自研规则） | 字符串/数值 | 固定值 | 状态字段、类型字段的非法枚举 |
| 枚举值，单日，异常值数量（自研规则） | 字符串/数值 | 固定值 | 日更表昨天非法枚举 |
| 枚举值，全表，异常值个数/总行数（自研规则） | 字符串/数值 | 百分比 | 非法枚举占比 |
| 枚举值，单日，异常值个数/总行数（自研规则） | 字符串/数值 | 固定值 | 日更表昨天非法枚举占比或数量控制 |

## 4. 当前规则到 BI 内置规则的映射

| 当前治理规则组 | 优先 BI 配置项 | 日期口径 | SQL 规则是否需要 |
| --- | --- | --- | --- |
| 昨天业务日期行数存在 | 表规则：单日行数，固定值 | 日更 T+1 统一传昨天 | 不需要，除非 BI 无法绑定日期字段 |
| 任务产出行数非零 | 表规则：单日行数，固定值；或任务级产出行数配置 | 使用任务实例日期/昨天 | 通常不需要 |
| 行数波动 | 表规则：单日行数，1、7、30 天波动率 | 日更表用昨天 | 不需要，阈值需人工确认 |
| 主键非空 | 字段规则：空值个数，固定值 | 日更表用昨天 | 单字段不需要；组合主键需要 SQL |
| 主键重复 | 字段规则：重复值个数，固定值；重复值个数/总行数，固定值 | 日更表用昨天 | 单字段不需要；组合主键需要 SQL |
| 核心字段空值 | 字段规则：空值个数，固定值；空值个数/总行数，固定值 | 日更表用昨天 | 不需要 |
| 金额字段非负 | 字段规则：最小值相关规则 | 日更表用昨天 | 文本金额需先确认 BI 是否支持数值转换，否则 SQL 兜底 |
| 金额极值/波动 | 字段规则：最大值/最小值 1、7、30 天波动率 | 日更表用昨天 | 不需要，阈值需历史证据 |
| 核心对象数波动 | 字段规则：唯一值个数 1、7、30 天波动率 | 日更表用昨天 | 不需要 |
| 枚举合法性 | 字段规则：枚举值异常数量/占比（自研规则） | 日更表用昨天 | 不需要，前提是枚举值已确认 |
| 字段结构变化 | 当前 9.1.3.11 未看到字段结构模板 | 不适用 | 需要 SQL 或平台其他功能 |
| 上下游一致性 | 当前 9.1.3.11 未看到跨表对账模板 | 不适用 | 需要 SQL |

## 5. 对第一批规则的优化口径

1. `DWS_抖音_SPU销售明细(dws_douyin_spu_sales_detail)` 第一条规则不应使用 SQL 规则作为首选。
   - 首选：表规则 `单日行数，固定值`
   - 日期字段：`pay_time`
   - 日期参数：昨天业务日期
   - 阈值：行数大于 0
   - 用途：检查 T+1 昨天数据是否到达

2. 主键和核心字段检查优先拆成字段规则。
   - `__id` 非空：字段规则 `空值个数，固定值`
   - `__id` 重复：字段规则 `重复值个数，固定值`
   - `pay_time`、`spbm`、`account_amount`、`bhstghf`、`cgje` 等核心字段：字段规则 `空值个数，固定值` 或 `空值个数/总行数，固定值`

3. 金额字段先按字段类型分流。
   - 如果 BI 识别为数值字段：优先用 `最小值` 或 `单日最小值` 检查非负，用最大值/最小值波动检查极值。
   - 如果字段是文本格式：不能直接配置数值阈值；先配置空值、枚举/格式类规则，数值可转换性暂时用 SQL 兜底，或等字段类型治理后再改为内置数值规则。

4. 行数波动规则不作为第一条上线规则。
   - 第一条先检查昨天是否有数据。
   - 波动率规则需要历史运行数据和业务阈值确认。
   - 默认不要假设 50%/200% 是正式阈值，只能作为待确认建议。

5. 大表必须使用日期参数或任务产出指标。
   - 日更 T+1 表只查昨天，不查全表。
   - 没有可靠业务日期字段时，优先用任务产出行数。
   - 不为了配置字段规则而对大订单表做全表重复/空值扫描。

## 6. 后续配置顺序

1. 先为每张表确认是否有可靠业务日期字段。
2. 日更 T+1 表优先配置 `单日行数，固定值`。
3. 再配置主键/核心字段的字段规则。
4. 金额字段只在字段类型可靠时配置数值类规则。
5. 枚举规则必须先有合法枚举值清单。
6. SQL 规则只用于内置模板覆盖不了的情况。
