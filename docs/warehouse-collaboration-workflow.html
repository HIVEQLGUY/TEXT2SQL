谁在什么时候做什么

把协作职责和技术动作分开，避免业务方被目录和命令淹没。

你 / 业务方
确认业务范围、字段语义、业务粒度、指标口径，以及影子结果是否可用于分析。
我 / 建模助手
盘点旧逻辑，统一中文字段名和物理字段名，固化清洗契约，生成 SQL、质量检查和发布包。
ClickHouse
先写候选表或影子表，质量通过后才切换唯一正式表；历史版本通过 Git 规则重建。
平台留痕
OpenMetadata 登记元数据，Git 保存契约、SQL、报告、标签和回滚依据。

一份规则，三个落点

数据、元数据和版本记录各自负责什么。

ClickHouse只保存当前正式 DWD 和当前待审阅影子结果；已晋级、退回或过期的影子表与历史备份通过清理发布删除，清理前先通过元数据只读计划。
OpenMetadata保存当前表、字段注释、粒度、枚举、标签和血缘；被删除的旧表资产通过退休清单回读确认。
Git / origin保存可重建的清洗契约、建模 SQL、发布 YAML、清理 SQL、质量 SQL、报告和发布标签，不保存数据行备份。
