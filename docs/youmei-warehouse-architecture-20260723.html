五、Git 可重建型版本管理方案

默认不永久保留多份正式物理表。Git 保存完整可重建发布包，ClickHouse 保留当前生效结果和必要短期版本，OpenMetadata 记录治理状态。
1

规则入库

模型 SQL、DDL、迁移、测试、清洗契约、元数据契约、血缘和发布清单进入 Git。

2

影子构建

按 Git 中的发布包在 ClickHouse 构建影子表或 staging 表，执行质量门禁。

3

正式切换

质量通过后切换当前视图或生效指针，记录发布版本、运行批次和源分区边界。

4

治理同步

OpenMetadata 回写表、字段、枚举、标签、血缘、质量状态和当前生效版本。

5

回滚重建

需要回滚时从 Git 取旧发布包，重建旧版本，验证后重新切换当前视图。

核心原则

聊天结论不能作为唯一规则来源。长期规则进入 Skill，模型规则进入 Git 发布包，表和字段治理进入 OpenMetadata，执行状态进入 ClickHouse 元数据控制库。

规则可复用 发布可重建 治理可回读
